# ND Attire

Ecommerce site for **ND Attire**: handpainted mekhela sador, sarees, bridal dupattas and handloom cotton sets by Nikita Dutta. Orders go to WhatsApp, so there are no payments on the site yet.

Next.js 16 (App Router, fully static) · TypeScript · Tailwind CSS 4 · Motion · Zustand

## Run it

```bash
npm install
npm run dev          # http://localhost:3000
npm run build        # production build (must pass with no type errors)
npm start            # serve the production build
```

Node 20.9 or newer.

## Add a product

It's a one-file change, plus a photo.

1. Save the photo as `source-images/products/<slug>.jpg`, for example `hp-peacock.jpg`. If you have a high-resolution original, put it in `source-images/originals/<slug>.jpg` instead (or as well). Originals always win.
2. Run the image pipeline (see below), or just `npm run images -- hp-peacock` to process only the new photo.
3. Add an entry to `src/data/products.ts`:

```ts
{
  slug: "hp-peacock",                      // matches the photo name; becomes /product/hp-peacock
  name: "Peacock handpainted saree",
  category: "handpainted",                 // handpainted | bridal | designer | handloom | everyday | offers
  description: "Peacock feathers painted on ivory",   // one line, shown on cards
  price: null,                             // a number in rupees, or null for "Price on request"
  images: ["products/hp-peacock"],         // first is the cover; add more for a gallery
  soldOut: false,
  featured: true,                          // featured pieces lead the shop's default sort
  newArrival: true,                        // shows in "New arrivals" on the home page
  alt: "Ivory saree with handpainted peacock feathers",
  colours: [{ name: "Ivory", family: "White", swatch: "#f4efe6" }],
  // sizes: ["S", "M", "L"],               // only for stitched pieces; adds a required size picker
  // details: { fabric: "…", care: "…", delivery: "…" },   // shown only when filled in
},
```

**Colours and sizes.** One colour is shown as a fixed label. Two or more colours show a picker the customer must use before enquiring or adding to the bag; give each colour its own `image` so the gallery switches to it, and set `soldOut: true` on a colour to grey it out. `family` groups shades for the shop's colour filter (e.g. "Wine" under "Red"). Sizes work the same way, and turn on the size guide once `sizeGuide` in `site.ts` has rows. No product has sizes yet because none were confirmed.

To mark something sold out, set `soldOut: true`. To change a price, edit `price`. Bags drop anything that is no longer orderable.

Link to a colour directly with `/product/<slug>?colour=Wine`. The five handloom pieces that used to have their own pages now live on `hl-wash-cotton` and `hl-staple-cotton` as colours; their old URLs redirect (see `movedProducts`).

## Images

The pipeline needs Python 3.10+ (one-time setup):

```bash
python3 -m venv .venv
.venv/bin/pip install -r scripts/requirements.txt
npm run images            # all photos → public/images + src/data/image-meta.json
npm run logo              # logo → public/brand, favicons and src/app/opengraph-image.png
```

For each photo it:

1. Uses `source-images/originals/<slug>.*` if one exists, skipping cleanup and upscaling.
2. Finds burned-in text (RapidOCR) and masks the top-right corner where Instagram icons sit, then inpaints those areas. If the text sits on busy fabric and a clean 4:5 crop exists, it crops instead.
3. Upscales 4× with Real-ESRGAN (x4plus, on CPU), then applies a light sharpen, a gentle contrast/vibrance lift and a shared warm grade.
4. Crops to 4:5 around the subject and exports AVIF + WebP at 1600 px and 800 px, plus a blur placeholder.
5. Writes `scripts/output/review.html`, with before, mask and after for every photo and a list of flagged ones.

Per-photo fixes live in `scripts/image-overrides.json`: `trim` (cut strips off the edges), `extra_mask` (areas OCR missed), `mode` (`"crop"` or `"inpaint"`) and `focus` (crop centre).

**Swapping a photo:** replace the file in `source-images/` (or add an original), then run `npm run images -- <slug>`. The site picks it up on the next build.

> The brief asked for EasyOCR + LaMa (IOPaint) and the Real-ESRGAN binary. Their weights download from GitHub and Hugging Face, which were blocked where this was built. The pipeline therefore uses tools whose models ship inside PyPI wheels: RapidOCR, OpenCV FSR inpainting, and Real-ESRGAN x4plus weights run through ncnn on CPU. If `iopaint` is installed and can load LaMa, the script uses it automatically, which noticeably improves the cleaned areas.

## Deploy to Vercel

1. Push this repo to GitHub, then on vercel.com choose **Add New → Project** and import it. The defaults (Next.js, `npm run build`) are correct.
2. Under **Settings → Environment Variables**, set `NEXT_PUBLIC_SITE_URL` to the live domain (for example `https://ndattire.in`). It is used for canonical URLs, the sitemap, Open Graph and structured data. Until it is set, the Vercel production URL is used.
3. Add the custom domain under **Settings → Domains**.

The build is static, so images are served through Vercel's image optimiser, which serves AVIF/WebP at the right size.

## Checkout

`src/lib/checkout.ts` defines a `CheckoutProvider` interface. Today `checkout = whatsappCheckout`, which builds this message:

```
Hi ND Attire, I'd like to order:

1. Handloom wash cotton mekhela sador
   Colour: Wine
   Quantity: 2 · ₹1,500 each
   https://…/product/hl-wash-cotton
2. Lavender handpainted saree
   Colour: Lavender
   Quantity: 1 · Price on request
   https://…/product/hp-lavender

Subtotal (priced items): ₹3,000
Please confirm availability, delivery charges and the final total.

Name: <name, if given>
Delivery address: <address, if given>
```

The product page's **Enquire on WhatsApp** button sends:

```
Hi ND Attire, I’m interested in <Product Name>.
Size: <size, or "Not applicable">
Colour: <colour, or "Not applicable">
Quantity: <qty>
Product link: <product URL>
Please confirm availability and ordering details.
```

The contact page form has no server: it validates, then opens WhatsApp (or the customer's email app, once `email` is set) with the enquiry filled in.

To add Razorpay later, implement `CheckoutProvider` (create the order on a server route, open Razorpay Checkout in `submit`) and point `checkout` at it. No UI components need to change.
